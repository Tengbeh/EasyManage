# EasyManage implementation contract
API and storage reference for EasyManage 1.0. Requires Node.js 22.12 or newer.

## API conventions
All API responses `{data:T}`; lists `{data:Record[],meta:{total,page,pageSize}}`; errors `{error:{code,message,details?}}`. snake_case record fields from requested schema. UUID IDs as named fields employee_id etc. Monetary values decimal strings with two digits. Dates ISO. Role strings `administrator`, `hr`, `accountant`. Status strings lower-case snake_case. User me `{data:{user,permissions:string[],csrfToken,connection:{configured:boolean,connected:boolean}}}`. Unauthorized /me 401. GET /api/health public `{data:{status,googleConfigured,sheetsConfigured}}`; frontend login shows truthful setup state with link `/setup` (static guide). GET /api/auth/google redirect, callback; POST /api/auth/logout. Fetch credentials include, mutating x-csrf-token from me. For retry prevention frontend send fresh Idempotency-Key crypto.randomUUID per form submission retained through retries. Do not use demo login or storage fallback. Tests may inject memory repository only.

## Resources
GET list and GET /:id, POST creation, PUT /:id updates: /api/employees, /departments, /bonuses, /penalties, /loans, /attendance, /leave, /users. Appropriate limitations sensitive updates. list query search, page, pageSize, department_id, employment_status, employee_id, month, year, status, sort, direction. Employee profile GET /:id returns the employee object; histories use separate resource queries. Employee salary adjustments POST /employees/:id/salary `{basic_salary,allowances,payment_frequency,effective_date,reason}`; GET same history. PATCH /employees/:id/status `{employment_status,employment_end_date?}`. /bonuses/:id/approve and /reject PATCH; penalties same. /loans/:id/approve, /reject POST; GET /loans/:id/installments; POST /loans/:id/payments `{installment_id,amount,payment_date}`. /leave/:id/approve,reject PATCH.
GET /settings returns company object, PUT updates. GET /audit-logs. Notifications GET list and PATCH /notifications/:id/read; derived notifications okay plus read state.

Payroll GET /api/payroll = runs. POST /preview `{payroll_month}` returns `{rows:PayrollRow[],totals:...,warnings:string[]}` no persistence. POST /generate `{payroll_month}` persists draft same shape + run. GET /:id `{run,rows}`. POST /:id/submit, /approve, /reject {reason}, /finalize, /paid; PUT /:id/adjustments `{employee_id,allowances,other_deductions,tax_deductions,reason}` draft only. Explicit permission payroll.approve controls approval; generation cannot imply paid. One run/month; rejected may be regenerated through explicit revision operation or draft edits. No silent final mutation. Reports GET /api/reports/:type?month&year&employee_id&department_id&format=(json|csv|xlsx|pdf); default json list envelope. types employees,active-employees,inactive-employees,new-employees,departments,terminations,attendance,leave,payroll,annual-payroll,salaries,bonuses,penalties,loans,loan-repayments,outstanding-loans,deductions,gross-net. Payroll reports finalized snapshots only.

Permissions keys: employees.read/write, salaries.read/write, banking.read/write, departments.write, bonuses.read/write/approve, penalties.read/write/approve, loans.read/write/approve, payroll.read/generate/approve/finalize/pay, attendance.read/write, leave.read/write/approve, reports.hr, reports.finance, users.manage, settings.manage, audit.read. Auth role defaults backend and allow explicit permission grants stored Users.permissions column. Frontend only uses returned permissions.

Dashboard GET /api/dashboard?month=YYYY-MM returns {metrics:{total_employees,active_employees,inactive_employees,on_leave,monthly_gross_payroll,monthly_net_payroll,total_bonuses,total_penalties,outstanding_loans,pending_payroll_approvals},payroll_trend:[{month,gross,net}],department_distribution:[{name,value}],status_distribution:[{name,value}],bonus_penalty_trend:[{month,bonuses,penalties}],loan_repayments:[{month,amount}],recent_employees:[],recent_activity:[],pending_approvals:[],upcoming_end_dates:[],recent_adjustments:[],upcoming_installments:[]}. Only expose permitted metrics.

## Storage and payroll engine interface
Repository exported interface uses `list(table):Promise<Record<string,any>[]>`, `commit(changes:Array<{table:string,record:Record<string,any>}>):Promise<void>` upsert and atomic Sheets batchUpdate across sheets, `initialize():Promise<void>`. Cached lists TTL 15s, explicit invalidation; serialized mutating service calls (single writer server). Read required sheets once per request. Add worksheets Salary_History, Leave, Notifications_Read, Idempotency as needed. Required original schemas preserve all columns, append extra columns.
The pure payroll engine implements `calculatePayroll(input:{payroll_month:string,employees:any[],salary_history:any[],bonuses:any[],penalties:any[],loans:any[],installments:any[],settings:any,existing_payroll?:any[]}):{rows:any[],totals:any,warnings:string[]}`. Throws Error invalid dates/money etc. All money strings. Per-row includes installment_allocations:[{installment_id,loan_id,amount}], bonus_ids, penalty_ids. Engine input settings configured_deductions JSON/string supports tax_percent,other_deductions,allowances,deduction_limit_percent; rows derived from dated salary history (effective_date) fallback hire baseline. Frequency monthly/weekly/daily/custom via days-per-cycle config, proration by eligible calendar days in the configured cycle; rejects unsupported custom until configured. total fields total_basic_salary,total_allowances,total_bonuses,total_gross_salary,total_penalties,total_loan_deductions,total_deductions,total_net_payroll,total_employees. Engine never marks paid. Finalize reserves installment allocation; payments actual reconcile same installment once. Salary changes preserve baseline to calculate old periods. Backend builds validated input and stores snapshots JSON extra columns.
